# Issue #217: 純正 CD_SEEK ($04 / $E00C) JSR の安全可否裁定

## 結論
**BLOCKED。** 純正 callee の JSR は実行しない（JSR 回数 0）。#218 は本 PR の判定対象外であり、本 PR は #218 の実行を許可しない（扱いは「次段階（#218）の判定」節）。

理由は次の 2 点に集約される。
1. callee のバイト列・ABI（戻り値、フラグ、エラー、完了条件）が未確認（#13 で UNKNOWN）であり、副作用集合を有限に確定できない。
2. pinned Geargrafx `b49ae82a` 実コアには、列挙できた副作用（VDC/ST 迂回、CD デバイス書込み、IRQ、MPR 動的変更）に対して、本記録の調査範囲では副作用発生前に一般的に遮断する手段は確認されていない（網羅的な測定は未実施）。本表の調査範囲で確認されている事前遮断は、`$1804` の既知 PC 限定のもの（#194 / #200 の記録）と、合成 TAM 直後の境界停止（H5、一般化しない）である。後者は TAM 実行後に後続命令を止めるもので、MPR 変更そのものの事前遮断ではない。CPU 経路の RAM 書込み拒否（H6）は別の項目として扱う。

これは「安全が確認できない」ことの裁定であり、「callee が危険である」ことの証明ではない。純正 BIOS は読み込まず、そのバイトも実行していない。

## 対象と範囲
- 対象: slot `$04` / 候補 `$E00C` `CD_SEEK`（親 #13、関連 #3 / #5 / #6 / #8 / #12 / #173）。

- 既存の契約判定コード（`tools/cdreset_safety_preflight.py` など、#211〜#213 が変更中のもの）は変更していない。

### 源泉間の不整合（開示）
- `docs/cd-reset-contract.md`（78 行付近）は #194 について "the pre-side-effect trap is BLOCKED" と記す一方、`geargrafx_mmio1804_preblock.py` は既知 PC の実行ブレークによる事前遮断を GREEN と記録している。両者は「一般的な `$1804` 事前遮断」と「既知 PC の事前遮断」を区別して読む必要がある。本記録は後者のみを認める。
