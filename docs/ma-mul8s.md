# MA_MUL8S 独自実装（Issue #74）

候補スロット `$40` / 候補エントリ `$E0C0` の `MA_MUL8S`（符号付き 8-bit 乗算）について、
本プロジェクト独自仕様の HuC6280 ルーチンを `src/math/ma_mul8s.s` に置く。
**リファレンス BIOS の MA_MUL8S 呼出規約は UNVERIFIED** であり、以下は本プロジェクトの定義にすぎない。
API ジャンプテーブルには**接続していない**（`release_eligible=false` のまま）。

## 本プロジェクトの仕様（参照 BIOS ABI ではない）

| 項目 | 定義 |
| --- | --- |
| 入力 | A = 被乗数、X = 乗数。どちらも 2 の補数の符号付き 8-bit（-128..127） |
| 出力 | X:A = 符号付き 16-bit 積の 2 の補数表現（X 上位、A 下位） |
| 値域 | -16256（-128×127）..16384（-128×-128 = `$4000`）。16-bit 符号付きに必ず収まるため**オーバーフローは発生しない** |
| 保存 | Y と P（PHP/PLP で N/V/D/I/Z/C を含め呼出前の値に戻す）。呼出側の D=1 でも内部は CLD して 2 進演算 |
| 副作用 | スタック 5 バイト（呼出 JSR の 2 バイトを除く）。ゼロページ・`$20F8-$20FF` は使わない |
| 前提 | MPR1 が RAM バンク `$F8` を写像し、スタックページが論理 `$2100` にあること |

アルゴリズムは符号なしシフト加算の後、`a<0` なら上位から b を、`b<0` なら上位から a を引く
（mod 2^16 の恒等式）。参照 BIOS のコードは参照していない。

## 検証（実際に実行したもの）

`tests/integration/geargrafx_ma_mul8s.py` がルーチンと独自ドライバ
（`tests/fixtures/ma_mul8s_driver.s`）を pinned cc65 で 8 KiB の HuCARD テスト ROM に組み、
pinned Geargrafx libretro コアで実行する。ホストは要求を RAM に書いてフレームを進めるだけで、
乗算はゲスト CPU が行う。全 65,536 組を host モデル（`signed(a)*signed(b) & 0xFFFF`）と照合し、
各呼出で Y（`b^$5A`）、S（釣り合い）、P（C=b bit0、D=b bit1 を変化させて前後一致）も確認する。
負の対照として `a<0` 補正（`sec; sbc $2102,x`）を NOP にした ROM が不一致で落ちることを実コアで確認する。
`tests/host/test_ma_mul8s.py` は境界値モデル、判定器の破損検出、上記の実コア実行を含み、
ツールやコアが無ければ SKIP ではなく失敗する。

2026-10-19 の WSL Ubuntu 実行結果:

| 項目 | 結果 |
| --- | --- |
| `python3 tests/integration/geargrafx_ma_mul8s.py` | PASS（exit 0）、65,536 組・不一致 0、1 行あたり最大 1 フレーム |
| 負の対照 | 期待どおり FAIL（32,640 組不一致 = a<0 かつ b≠0） |
| Geargrafx | `b49ae82a012eade566d72e9d61c9d95a5caa4da3`、core sha256 `38c9af41…ad52c` |
| cc65 | `71746c829e77f74c2b601a7d16821170c2610df3` |
| テスト ROM sha256 | `3e7de63b8ecd048ebe49560b850065cef5457df755026c832c0d0180f3970718` |

境界値（実コア観測、16 進）: `-128×-128=4000`、`-128×127=C080`、`-128×-1=0080`、`-128×1=FF80`、
`-1×-1=0001`、`-1×127=FF81`、`127×127=3F01`、`0×n=0000`。
