## Main measurement (2026-10-21)

The earlier 2026-10-20 reading of 1/81 (`963f3a36`) is superseded. The reference ABI remains **UNVERIFIED**; `release_eligible: false` and the BIOS release gate remain **BLOCKED**. This is a dated source inspection, **not** a claim of fresh CI success or a new Geargrafx run. The historical table below retains its original 2026-10-17 test scope.

- **Original routines, DEV-only or standalone (not verified firmware):** `EX_BINBCD`, `EX_BCDBIN` and `MA_MUL8U` are DEV ROM overrides (not approved, not ABI-verified); `MA_MUL8S` is standalone only; opt-in `routine-real-core` ([#328](https://github.com/mao2009/oss-pce-cd-bios/pull/328), [#331](https://github.com/mao2009/oss-pce-cd-bios/pull/331)). The CD test harness observes guest RAM/PC and SCSI events instead of injecting sectors. It requires **64 consecutive guest instructions at the success-halt loop**. READ(6) on a CD-DA track is an **observed Geargrafx quirk**, not confirmed hardware behavior. **Main now has four development-only ROM implementations (`EX_GETVER`, `EX_BINBCD`, `EX_BCDBIN`, `MA_MUL8U`), none approved or ABI-verified; this is not a compatible BIOS.** There is still no callable `CD_RESET`/`CD_BASE`/`CD_READ`, firmware-mediated CD boot, retail game boot, independent-emulator or physical-hardware compatibility result. The 90-function/270-scenario plan does **not** mean those scenarios all ran or passed. Reference BIOS images are private, optional local inputs and never repository deliverables.

## Remaining unimplemented services and evidence boundary

- `CD_RESET` (`$01`), `CD_BASE` (`$02`) and `CD_READ` (`$03`) remain **without callable firmware implementations**, despite related host models and real-core bus/transport diagnostics. See [#11](https://github.com/mao2009/oss-pce-cd-bios/issues/11), [#12](https://github.com/mao2009/oss-pce-cd-bios/issues/12), [#147](https://github.com/mao2009/oss-pce-cd-bios/issues/147), [#148](https://github.com/mao2009/oss-pce-cd-bios/issues/148) and [#149](https://github.com/mao2009/oss-pce-cd-bios/issues/149).
- The 77 remaining table slots are nonreturning stubs. `spec/api_contracts.json` tracks **reference BIOS evidence**, so its `implementation_status: NOT_STARTED` or `verification: NOT_RUN` entries must not be reinterpreted as a denial of the separate DEV-only `EX_GETVER` implementation. Conversely, real-core observation of that implementation does **not** promote the reference ABI to VERIFIED.
- The synthetic sector-to-RAM executable experiment [#122](https://github.com/mao2009/oss-pce-cd-bios/pull/122) is **not** BIOS-mediated disc boot. Host models, raw SCSI experiments, stub/slot tests and signed evidence are not retail-game compatibility results.
- Main CI provenance tooling can produce and verify attested diagnostic evidence and a signed verdict, but the trusted `VERIFIED` promotion path is intentionally **BLOCKED** pending the approval/protection/enablement boundary in [#171](https://github.com/mao2009/oss-pce-cd-bios/issues/171). Attested diagnostic PASS does not assert `CD_READ` callee compatibility.
- PR state is dynamic: consult [open pull requests](https://github.com/mao2009/oss-pce-cd-bios/pulls) rather than treating an older Draft list as current.
