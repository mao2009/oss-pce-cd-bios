# Phase C3: synthetic-BIOS tests (Issue #291)

Scope: reproducibility, seeds, trace, input and portable isolation, using a SYNTHETIC BIOS written for this test and the unmodified synthetic CUE/BIN from `<SYNTH_MEDIA>/`. No System Card or reference BIOS was used, no reference JSR was run, `rom/` was not opened, no commercial medium was used, and nothing was written to GitHub. The result says nothing about the System Card BIOS or any game.

## Commands (exact)
- Synthetic BIOS: `py -3 scratchpad/phase-c/synthetic/make_synthetic_bios.py`
- Harness (all launches and T1 to T5 except T2 re-evaluation): `timeout 1200 py -3 scratchpad/phase-c/synthetic/run_c3.py full` (stdout in `c3-full-stdout.txt`). It launches `geargrafx.exe --headless --mcp-stdio --portable` in each new run directory `scratchpad/phase-c/runs/<label>/`, with `GG_TEST_RNG_SEED` set for det runs (`0x00C0FFEE` for seed A, `0x0BADF00D` for seed B), and drives it with MCP JSON-RPC over stdio.
- Per-launch sequence: `load_bios` (synthetic, type syscard), `load_media` (synthetic CUE), wait until paused at `$E000` (emulator pauses on load), read CPU state twice 0.5 s apart, `set_trace_log` (cpu.instructions, memory), breakpoints at `$E012` and `$E028`, `debug_continue`, optionally `controller_button` (player 1, up, press) at `$E012`, `debug_continue`, `get_trace_log`, `read_memory` (SYSTEM RAM 8192 bytes and LOGICAL 65536 bytes), `get_cdrom_status`.
- T2 re-evaluation (no new launches): `py -3 scratchpad/phase-c/synthetic/reeval_t2.py`
- Default-OFF: `py -3 scratchpad/phase-c/synthetic/default_off.py`
- Isolation manifests: `py -3 scratchpad/phase-c/synthetic/manifests.py`

Each run's exit code was 0 (`exit_code` in each run record). No process was left behind.

### T1 (reproducibility): PASS
- Seed A, three launches (`det_S1_r1..r3`): post-reset state equal; halt state equal; SYSTEM RAM SHA-256 `133b6ba7f4385304...` equal; LOGICAL SHA-256 `3e6c4854206a1cff...` equal; CD status equal (BUS FREE, reset 0, length 00:02:16, 16 sectors, next event NONE); trace equal (16 PCs).
- Pinned baseline, three launches separated by 1.5 s: 3 distinct post-reset states, 3 distinct halt states, and 3 distinct LOGICAL hashes. The SYSTEM RAM hash is the same in all pinned runs (`133b6ba7...`), because the synthetic program writes only fixed values there. The variance is in CPU registers and MPR mapping, which are not in SYSTEM RAM.

### T2 (different seeds): PASS (after model correction)
- Seed A (`0x00C0FFEE`) and seed B (`0x0BADF00D`) differ in A, X, Y, S, P and MPR (`differing_fields`).
- Same seed, 3 runs each (6 runs in total): identical within seed.
- Model check (corrected): for each of the 6 det runs, the observed A, X, Y, S word is the xorshift32 output at index `rnd_index` (1040 for seed A, 1039 for seed B) of the stream from the seed; the observed MPR0-6 are the first seven non-zero `Next8Bit` values at index 521 (seed A) or 520 (seed B). Observed P equals the masked draw (see below). `cpu_regs_match_model` and `mpr_match` are true in all 6 runs.
- This check shows that the seed controls the reset state as the source describes, which is the seed-reaches-RNG evidence that the stderr log could not provide (the `TEST ONLY` line did not appear in any captured output).

### T3 (trace after reset): PASS
- Trace enabled at `$E000` (paused, after reset), then run to `$E028`.
- Every det run: 16 entries; PCs equal to the expected sequence. Entries include the instruction text (for example `E006 STA $2000`, `E012 LDA $1000`).
- Zero-entry check: no run has zero trace entries (0 entries = FAIL; none found). Per run: det_S1_r1..r3, det_S2_r1..r3, det_S1_up_r1 all 16.

### T4 (input): PASS (after relation correction)
- No input (`det_S1_r1`): SEL=0 read at `$2010` = `3F`; SEL=1 read at `$2011` = `3F`.
- Up pressed at `$E012` (`det_S1_up_r1`): SEL=0 read `3F` (unchanged); SEL=1 read `3E` (bit 0 cleared).
- Input is visible in the CPU read, and the value is recorded to RAM and read back (`wram0011`). The API success alone was not used as evidence.

### T5 (isolation): PASS, with one note
- Per run, the new files beyond the executable and `SDL3.dll` are only `config.ini` and `stderr.txt` (the harness log). Nothing was changed or removed in the run directory. `tmp/` is created by the emulator (present in the directory listings). Full before and after manifests: `phase-c3-manifests.json`.
- Outside the run directories, unchanged: the media directory (manifest equal before and after), the synthetic BIOS hash, the pinned binary hash, and the pinned build's `config.ini` hash.
- Config path keys (`config.ini`, 80 path keys across the 10 full-run launches, 8 keys each): 70 resolve inside their run directory. The other 10 are `RecentROM0` (the recent-media list), which stores the CUE path as read (`<SCRATCH_WORKER>/.../synthetic_cd.cue`). This is a reference written into the config, not a file written outside. Recorded here as found; it is not a write violation.

## Model corrections (made after first observations; both from source)

1. **T4 joypad bit relation.** The first draft of T4 expected Up to clear bit 0 of the SEL=0 read. A probe run showed the SEL=1 read changed instead. Source: `src/types.h:77-83` (Up = 0x10, high nibble) and `src/input_inline.h:174-180` (SEL=0 returns the low nibble, SEL=1 the high nibble). The expectation was corrected to: SEL=0 low nibble unchanged, SEL=1 low nibble bit 0 cleared. This correction was made before the full run. The corrected expectation is recorded in `phase-c3-expected.json` (T4 field with a note).
2. **T2 P term.** The first full pass failed on T2 because the xorshift model compared the raw draw for P. A, X, Y, S and MPR matched exactly in all runs. Source: `src/huc6280.cpp:232-240`, after the random P draw, reset clears T (0x20), clears D (0x08), sets I (0x04), and clears B (0x10). The model now uses `P = (raw & ~0x38) | 0x04`. T2 was re-evaluated from the saved per-run states (`reeval_t2.py`); no new launches were made. First-pass output is in `phase-c3-results-firstpass.json`.

## Default-OFF (C1)
`c1-default-off-check.json`: two launches of the test binary without `GG_TEST_RNG_SEED`: post-reset state differs between launches (time seed, as in the pinned binary), and the string `TEST ONLY` appears in no run directory.

## Limits
- The post-reset state is read at the load-time pause at `$E000`, with no instruction executed yet. This was confirmed by pausing (`debug_get_status` paused=true, PC=E000), not by a breakpoint on reset.
- The `TEST ONLY` log line from the seeded binary was not observed in the captured output. Opt-in evidence is the seed-model match in T2.
- The synthetic program does not use the CD and does not test the System Card boot path. Nothing here is a claim about System Card or commercial-game behaviour.
- Geargrafx output is not hardware evidence.
- Single host (Windows 11) and one emulator build. No other host or build was tested.
