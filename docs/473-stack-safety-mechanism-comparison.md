# #473 スタック安全機構の方式比較（A / B / C）

## 位置づけ

- 本書は、#473 の方式選定に必要な**証拠の整理と比較**である。**方式を決定する文書ではない。** 決定はオーナー判断（末尾「オーナー判断事項」）。
- **本番用安全ガードは有効化しない。** 実装コードは含まない。#459 / #367 のゲートは **BLOCKED のまま**。`release_eligible=false`、`BLOCKED_ABI` は変更しない。VERIFIED / DEV_CALLABLE は付与しない。
- 純正 BIOS、商用ゲーム、CD_BOOT / CD_EXEC、純正 JSR は実行していない。ROM のバイト列・逆アセンブルは含まない。
- 根拠は既存の観測だけである。本書で新しい実コア計測はしていない（`NOT_RUN`）。

## 1. 既存観測の再評価

出典：`docs/367-block-transfer-audit.md`（#470、合成 BIOS・合成メディア、pinned Geargrafx b49ae82）、`docs/473-caller-stack-experiment.md`（#481、合成 HuCARD、無改造コア）、`docs/173-safety-monitor-limits.md`。

### 1.1 事実として確定しているもの（実コア観測）

| 番号 | 観測 | 出典 |
|---|---|---|
| O1 | TransferStart の A/X/Y push が MPR1=$FF で VDC に着地した（フック無し）。AR 0→7、R[7] 0→564 | #470 |
| O2 | push を書込み前に拒否すると、AR・R[7] は不変、S は釣り合う。ただし TransferEnd は常に 3 スロットを pop する | #470 |

### 1.2 再評価で分かったこと

1. **根本原因は「スタックページ（`$2100〜$21FF`、MPR1）が $FF（I/O）を指していること」である。** push の書込みも pop の読出しも、同じ原因から副作用を起こす。#470 は書込み側（push）を、#481 は JSR の push を、それぞれ別の入口で見たに過ぎない。
2. **push 側だけを守る方式は、pop 側の読出し副作用を残す（O3）。** これは #470 が既に示した。
3. **呼出し側ガード（JSR の後で MPR1 を検査する）は、JSR 自身の push を守れない（O6）。** JSR・PHA・PHP・割込み入口・BSR は、いずれも命令自身が積むので、命令の外にある検査では間に合わない。
4. **#470 の probe は MPR1 を `SetMpr` で直接設定している**（`geargrafx_block_write_guard.cpp` の `memory->SetMpr`）。ゲスト命令の TAM を経由していない。#481 は ROM 内の TAM で MPR1 を設定している。方式 A を TAM の実行時に効かせる場合、#470 の probe のままでは「TAM を通らない設定」を検査できない。この差は後述の分割案で扱う。
5. 本書の観測は 1 バイト転送、MPR1=$FF の 1 例のみである。他の長さ、他のバンク（ROM、BRAM など）、NMI、実機のタイミングは未検証。

## 2. 方式の定義（本書での解釈）

| 方式 | 定義 | 検査する時点 |
|---|---|---|
| A | スタックページ（MPR1）が許可バンクでない状態を**事前に拒否**する。許可バンクは WRAM（$F8）のみとする | MPR1 を変える操作（TAM）の時点、または JSR / 転送などの入口の前 |
| B | TransferStart の push から TransferEnd の pop までを一括で保護する（pop 側の読出しも覆う） | TransferStart から TransferEnd まで |
| C | スタックへのアクセス（push・pop）が起きる**直前に**、命令の実行を止める | 各スタックアクセスの直前 |

「拒否」「止める」は、ハーネスが実行を打ち切ることを指す。ゲストの命令の意味を変えて続行することではない。

## 3. 方式ごとの評価

### 3.1 方式 A：MPR1 の危険マッピングを事前拒否

| 観点 | 評価 |
|---|---|
| 安全性（範囲） | MPR1 が $FF にならなければ、push・pop・JSR・BSR・割込み入口・RTS・RTI・TransferStart/End の**すべてのスタックアクセス**が I/O に届かない。原因側を断つので、最も広く覆える |
| TransferEnd の pop | 覆える。push を一度も書かない状況自体が起きない（TransferStart の前に拒否済み）。転送は 1 命令内で完結するため（O9 は IRQ が転送の途中で受理されないことを示す。実機は未確認）、転送中に MPR1 が変わる経路は観測されていない |
| JSR | 覆える。JSR の push より前に拒否する。ガードを JSR の後に置く方式（O6）と違い、命令自身の push が I/O に届かない |
| 実装箇所（案） | (a) 検証専用コアパッチで、MPR 書込み（TAM）の直前に MPR1 の新値を検査する。(b) 呼出し側契約：API 入口の前に MPR1 が RAM であること。実コアでは (a) が必要。pinned コアに該当フックは無く、新規パッチが必要 |
| 弱点 | (1) MPR1 を TAM 以外で設定する経路（リセット直後の初期値、ハーネスの直接設定）は検査できない。リセット直後の MPR 値は本書では未確認（UNKNOWN）。(2) 正規のゲームが MPR1 を一時的に I/O にする使い方を拒否する可能性がある。ただし本プロジェクトの用途（合成 ROM、DEV ROM）では対象外。(3) $FF 以外の危険なバンク（ROM、BRAM、CD RAM など）の扱いは未検証。許可バンクを WRAM のみにすれば安全側だが、過剰拒否になりうる |
| 未検証の副作用 | TAM を拒否した後の CPU 状態（PC、S、P、MPR）の扱い。ゲストが TAM を連続して実行する場合の途中状態 |
| テスト可能性 | 高い。#481 の CASE_IO（ROM 内の TAM で MPR1=$FF）がそのまま負例になる。MPR1=$FF 負例を保持する |

### 3.2 方式 B：push から pop まで保護

| 観点 | 評価 |
|---|---|
| 安全性（範囲） | **TransferStart / TransferEnd に限られる。** JSR、PHA、PHP、BSR、割込み入口は対象外。#473 の目的（JSR のスタック操作を守る）を満たさない |
| TransferEnd の pop | pop 側のフック（読出しの直前）を追加しない限り、O3 の副作用は残る。フックで pop を抑止して A/X/Y を元のまま保つ案（B'）は、状態は保てるが、転送本体を止めない（O4）ので、別途 #367 の宛先ガードが要る |
| JSR | 覆えない |
| 実装箇所（案） | 検証専用パッチの TransferStart フックと同じ位置に、TransferEnd 用の pop 前フックを追加し、フラグで対にする。コア内の `HuC6280` の転送終了処理 |
| 弱点 | (1) 範囲が狭い。(2) 抑止した pop と実機の pop の意味が異なる。(3) CPU の意味を変える（ゲストから見て A/X/Y の復元が起きない）。ただし、違反時に実行を打ち切るのなら問題にならない |
| 未検証の副作用 | pop 抑止後の S、P、PC。割込みが転送完了の直後に受理されるときの push（O9）は、B の範囲外 |
| テスト可能性 | 中。#470 の 5 命令の probe を流用できる。JSR は別試験が要る |

### 3.3 方式 C：副作用の前に命令実行を止める

| 観点 | 評価 |
|---|---|
| 安全性（範囲） | スタックのアクセス点（push・pop の共通処理）に置けば、JSR・PHA・PHP・割込み入口・RTS・RTI・TransferStart/End を一箇所で覆える。MPR1 がどう設定されたかに依存しない（TAM でも直接設定でも検出できる） |
| TransferEnd の pop | 覆える。TransferStart の最初の push の前に止めれば、pop は起きない |
| JSR | 覆える。JSR の戻りアドレス push の直前に止める |
| 実装箇所（案） | 検証専用コアパッチ：コアの stack push / pop 処理への書込み前・読出し前のフック。#470 のパッチは TransferStart の push に既にフックを付けており、同じ手法を広げる形になる。ただし、各命令（JSR、PHA など）が共通の push 処理を使うかは、コアのソースで確認していない（UNKNOWN） |
| 弱点 | (1) **命令の途中で止めた後の CPU 状態**（PC、S、P）が、命令の開始前と一致するかは未実測。#367 でも「命令途中の停止」は UNMEASURED。(2) #173 では ST・IRQ レジスタなどで、書込み前に止めるフックが無く BLOCKED と記録された（O10）。スタックのアクセス点で同じ制約が無いかは、コアのソース確認が先に要る。(3) コアの高頻度経路（push・pop）に手を入れるので、回帰リスクがある |
| 未検証の副作用 | 打ち切り後の VDC / PC / S / P / MPR。打ち切りがゲストの命令境界と一致するか |
| テスト可能性 | 高い。ただし「打ち切り後に状態が保存される」ことの実測が要る（解除条件 2） |

## 4. 比較表

| 観点 | A：事前拒否 | B：push から pop まで | C：副作用前に停止 |
|---|---|---|---|
| TransferStart の push | 覆う | 覆う | 覆う |
| TransferEnd の pop 読出し | 覆う（push 前に拒否） | 覆う（pop フックが必要） | 覆う（push 前に停止） |
| JSR / PHA / PHP / BSR | 覆う | **覆わない** | 覆う |
| 割込み入口の push、RTS / RTI の pop | 覆う（MPR1 が RAM のまま） | 覆わない | 覆う |
| TAM 以外で設定された MPR1 | **覆わない** | 覆う（転送の入口で検査） | 覆う |
| 検証済みの土台 | #481 の負例、#470 の MPR 観測 | #470 の probe | #470 のフック（TransferStart のみ） |
| 新規の実コアパッチ | TAM 前フック | TransferEnd の pop 前フック | stack push / pop 前フック |
| 打ち切り後の状態保存 | 未実測 | 未実測 | 未実測 |
| 回帰リスク | 低（MPR 書込み経路のみ） | 中 | 高（高頻度経路） |
| 推奨度（暫定。決定ではない） | 第一候補 | 単独では不十分 | 補完または第二候補 |

暫定の見立て：A は範囲が広く実装も小さい。ただし TAM 以外の設定経路を覆えないので、C を補完に使う案がありうる。B は JSR を覆えないので、単独では #473 の目的を満たさない。この見立ては**オーナーの承認を受けるまで採用しない**。

## 5. 検証条件（承認方式に共通）

拒否または停止の**後**に、次を拒否前と比較して一致させる。

| 項目 | 条件 |
|---|---|
| PC | 打ち切り点は命令境界（命令の実行前）か、定義した状態か。記録して一致を確認する |
| A / X / Y | 拒否前と一致（#470 で `$12/$34/$07` が壊れた事象の再発が無いこと） |
| S | 拒否前と一致、または定義した値 |
| P | 拒否前と一致（B フラグを除く扱いは #481 に合わせる） |
| MPR0〜7 | 8 本とも一致 |
| VDC | AR、R0、R[7]、ステータス（`$05` のまま）、データ読出しバッファ（`0xBEEF` のまま）が一致 |
| 宛先バイト | 転送本体が実行されない（宛先が元のまま） |
| WRAM のスタック画像 | 書込まれていない |

負例と正例：

| 区分 | 内容 |
|---|---|
| 負例（保持） | MPR1=$FF：5 命令（TII / TIN / TIA / TDD / TAI）、JSR（#481 の CASE_IO）、PHA / PHP、割込み入口 |
| 負例（追加案） | MPR1=ROM バンク、MPR1=BRAM、1 バイト以外の長さ、length 0 |
| 正例 | MPR1=$F8：#481 の CASE_RAM と #470 の stackwram が回帰せず PASS |
| 回帰 | #470 の 30 ケースが PASS のまま |
| 変異 | ガードを外した対照（#470 の unguarded）で、副作用が再現すること |

判定の曖昧さを避けるため、PASS には「拒否または停止が起きたこと」と「状態が一致したこと」の両方を要する。

## 7. オーナー判断事項

1. **方式の選択**：A / B / C / 組合せのどれを採るか。暫定の見立ては A（補完に C）。B 単独は #473 の目的を満たさない。
2. **許可バンクの範囲**：スタックページに許してよいバンクは WRAM（$F8）のみか。他のバンクを許す場合、その根拠が要る。
3. **「拒否」の意味**：ハーネスが実行を打ち切る（ゲストの意味を変えない）ことでよいか。B' のように pop を抑止して続行する案を認めるか。
4. **打ち切り後の許容状態**：PC は命令の実行前か、命令の途中を許すか。#367 の「命令途中の停止」は未実測のため、実測前に条件を決めるかどうか。
5. **MPR1 の設定経路**：TAM 以外（リセット直後、ハーネスの直接設定）を検査対象に含めるか。含めるなら A 単独では不足で、C が要る。
6. **コアパッチの方針**：検証専用パッチの拡大（TAM 前、stack push / pop 前）を認めるか。配布物に含めない方針（GPL-3.0 範囲）は維持するか。
7. **NMI の扱い**：pinned コアに NMI の受理経路が無い（#473 受入 7）。対象外のまま進めるか。
8. **#459 / #367 の BLOCKED 維持**：本書では維持。解除は S7 の判断。
9. **分割案の起票**：S1〜S7 のどれを起票するか、順序、優先度。

## 8. 未検証・限界

- 本書は既存観測の再評価で、新規の実コア計測は `NOT_RUN`。方式 A / B / C の安全性は、いずれも**実測前の評価**である。
- 打ち切り後の状態保存、命令途中の停止、TAM 前フック、stack push / pop 前フックは、すべて `UNMEASURED`。
- コアの push / pop が共通処理か、TAM の書込みがどの関数かは、コアのソースで確認していない（UNKNOWN）。
- 実機の挙動は未確認。合成 ROM・合成メディア・pinned コア（b49ae82）の範囲に限る。
