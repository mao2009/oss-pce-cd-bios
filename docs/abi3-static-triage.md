# Phase ABI-3：純正 System Card BIOS 81 スロットの静的トリアージ（Issue #476）

## 位置づけ

- 純正 ROM の 81 スロットを、既存の静的解析ツールで再解析した**静的プロファイル**である。
- **静的調査済みは ABI VERIFIED ではない。** 本台帳の全スロットで ABI 状態は `NOT_RUN` のままである。
- 純正 BIOS は実行していない。JSR 実行許可は 0/81（`tools/reference_jsr_gate.py --check` が 81/81 BLOCKED）。
- 静的プロファイルは探索可能だった範囲の静的所見であり、呼出しの許可ではない。未解決ターゲットの先は探索していない。

**判定：参照 ROM の正式な同一性は未確認である。** 台帳の再現性（同じ入力から同じ投影が得られること）と、入力 ROM の真正性（それが正式な参照画像であること）は別の事項として扱う。

- 再現性：本台帳はローカル画像 `rom/syscard3.pce` から再生成でき、既存 7 件の内容一致はテストで固定している。
- 真正性：CRC32 `6D9A73EF` の一致と既存 7 件の内容一致は、傍証にすぎない。CRC32 一致から SHA-256 同一性を主張しない。記録上の 262,656 バイト画像の SHA-256 とは照合できていない（ヘッダ 512 バイトが手元に無い）。
- 正式な参照 SHA-256 の確定は未了であり、オーナーの判断として残る（Issue #476 で追跡）。

- 入口：81 件すべて `JMP_ABS`、ターゲットは重複なし。

- ハザードが 1 件も無いスロット：$17、$1E、$22、$4A。

### 計測の読み方

- NO_RETURN を持つ 33 スロットは、`unresolved` が空でないスロットと一致する。NO_RETURN は未解決ターゲットでの打ち切りによる行き止まりを含むため、独立したハザードとして読まないこと。
- UNRESOLVED_TARGET を持つスロットは 20 件である。計上されるのは、呼出し・分岐・ジャンプ先を解決できない場合と、呼出し深さが上限を超えた場合である。表の数は「ハザードを持つスロット数」であり、ハザードの総数ではない。
- バンク未確定（`page_bank_unknown`）で打ち切られた経路は、UNRESOLVED_TARGET として計上されない。この打ち切りは 15 スロットで発生し、うち 12 スロットは UNRESOLVED_TARGET が 0 件である。

## ローカル再現手順と証拠レベル（#476）

| 証拠 | 結びつくもの | 強さ |
|---|---|---|
| 全体ファイル SHA-256 | ヘッダ付き 262,656 バイト／ヘッダなし 262,144 バイトの各ファイル全体 | バイト列を特定する。ヘッダの有無で値が変わる |
| ペイロード SHA-256 | 先頭 512 バイトを除いた 262,144 バイト | ヘッダ付き・なしの比較に使える。記録上の値は全体 SHA-256 のみで、ペイロード値との照合は未実施 |
| ペイロード CRC32 | Geargrafx DB のラベル | 識別ラベルにすぎず、出所の証明ではない |

- `python3 tools/reproduce_static_triage.py --rom <ローカル画像> [--expect-sha256 <オーナー確認済み全体SHA-256>]`（WSL、`TOOLS_DIR` に pinned da65）。画像が存在する場合、auditor 実行前に上表の値（サイズ、ヘッダ種別、各ハッシュ）を標準出力へ出す。`--expect-sha256` が無い間は同一性は UNVERIFIED と表示する。
- サイズが 262,144 でも 262,656 でもない画像は BLOCKED（終了コード 2）。`--expect-sha256` 不一致は FAIL（終了コード 1。auditor 失敗・投影差分も 1）。画像が無い場合も BLOCKED（2）。一致しても「オーナー提示の値とファイルが同じ」ことだけを意味し、VERIFIED ではない。
- TOCTOU 対策: 画像は 1 回だけ読み、そのバイト列でハッシュ・サイズ判定を行い、同じバイト列を非公開の一時ディレクトリ（リポジトリ外。権限 0700／ファイル 0600 は POSIX のみで、Windows では強制されない）へスナップショットとして書き、auditor にはスナップショットのパスだけを渡す。比較完了後に必ず削除する（try/finally）。削除に失敗しディレクトリが残った場合は stderr に `SNAPSHOT NOT DELETED: <path>` を出し、終了コードを 1 にする。画像のサイズは読み込み前に stat で判定する。元ファイルが検査後に変更されても結果に影響しない。
- `--expect-sha256` は厳格: 未指定は UNVERIFIED、64 桁 16 進（大文字小文字不問）なら比較、空文字・空白のみ・桁数違い・非 16 進・不一致は FAIL（1）。
- 終了コード: 0 = 全フィールド一致（PASS）、1 = FAIL（スナップショット削除失敗を含む）、2 = BLOCKED、3 = UNBASELINED（既存フィールドは一致、新指標は未検証）。リポジトリ内に本ツールの終了コードを使う Makefile／CI は無い。
- 投影の比較: 既存フィールドは値・構造・型とも厳密一致（JSON テキストで比較するため true と 1、4.0 と 4 は不一致）。解析器が後から追加した指標は名前付き許可リスト `ADDED_CALLEE_FIELDS`（現在 `states_without_guaranteed_return`、#485／PR #490）のみ、コミット済み証拠に無い場合に限り、型（int、bool 不可）・範囲（0 以上かつ `non_returning_states` 以上、`3 * states_visited + 1` 以下。上限の根拠: #490 は未知バンク・深さ超過・デコード不能の行き止まりも数えるが、それらは `states_visited` に入らず、復号済み状態の後続として高々 2 個ずつ（＋入口 1 個）しか生じないため。値は `states_visited` を超え得る）・位置（`apis[*].callee`）を検証したうえで比較から除外し、`UNBASELINED` を stderr に表示して終了コード 3 にする（PASS 行は出さない）。UNBASELINED は検証済み証拠ではない（この経路は意図的な非完全一致）。#490 の `budget_exhausted` が true のスロットでは新指標は下限値にすぎず、該当スロットを UNBASELINED 行に併記する。`--expect-sha256` は前後の空白を `strip()` してから判定する。許可リスト外の追加キー・その他の差分は FAIL。
- 正本の全体 SHA-256 が確定するまで、この手順の PASS は「ローカル画像から投影が再現した」ことのみを意味する。

## 制限

- 静的プロファイルは探索可能だった範囲の静的所見であり、安全性の保証ではない。ハザード 0 件でも安全を保証しない。
- 未解決ターゲットを含む 33 スロットは、呼出し先の完全な解析が未了である。未探索の経路には未知のハザードがあり得る。
- NO_RETURN は「どの後続からも復帰（rts/rti）に到達できない状態」を数える存在判定であり、全経路が必ず復帰することを証明しない。NO_RETURN=0 を復帰の証明として扱わない。全経路判定は別指標 `states_without_guaranteed_return`（Issue #485）で与える。
- `states_without_guaranteed_return` は「全後続が復帰に至る」最小不動点に入れない到達可能状態の数である。自己ループ・循環、未解決ジャンプ・呼出し、バンク不明、未デコード、呼出し深さ超過、探索上限で打ち切られた後続はすべて「保証なし」に数える（安全側）。分岐の成否は不明として両辺を可能とみなす保守的な上界であり、実行時に到達可能であることは意味しない。0 は静的グラフ上で全経路が復帰することのみを示し、安全性や実行許可を意味しない。逆に 0 でない値は、無限ループ・未解決の辺・カウンタ付きループ（`DEX; BNE` のように両辺を可能とみなす）を区別せず合算するため、非復帰の証拠ではない。スタック操作（復帰アドレスの書換え、`txs`）と割込みはモデル化していないので、0 でもモデル上の結果にとどまる。`budget_exhausted` が true のとき、探索上限で未展開のまま残った状態は到達可能状態に数えられないため、本値は過小計上（下限）となる。意味を持つのは `budget_exhausted` が false のときだけである。初回の再生成時は証跡 JSON に本フィールドが追加される。
- 既存の `non_returning_states` / NO_RETURN の意味と台帳（ABI-1/ABI-3）の数値は変更しない。新指標はプロファイルの追加フィールドであり、ハザード語彙・台帳スキーマには加えない。私的 ROM での再生成は未実施（NOT_RUN）で、台帳に新指標の値はない。
- 参照画像の正式な SHA-256 は未確定（上記）。
