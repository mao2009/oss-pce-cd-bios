# Issue #145: BIOS経由CDブート統合試験のフィクスチャと検査仕様

状態: **仕様のみ。サービス実装なし、試験コードなし、実行 NOT RUN。** 親は #5（`Refs #145`, `Refs #5`）。

## 0. 最重要の制約

- **本フィクスチャは「BIOS経由のブート成功」をシミュレートしない。**
  合成CDやホストモデルが「ブートした」ように見える出力を作っても、それは成功ではない。
- **成功の定義は、実コア（固定版 Geargrafx `b49ae82a`）が、本リポジトリのBIOSの起動経路と
  CDサービスを実際に実行してゲストへ制御を渡したことの観測のみ。** ホスト側の再現・HLE・
  ゲスト側が自分でマーカーを書く構成は成功にならない。
- 本書はどの項目も VERIFIED にしない。実コア観測が存在しない項目は UNKNOWN / BLOCKED と書く。
- #122（ゲストCD→RAM実験）は BIOS を経由しないため、本試験の証拠として流用しない。

## 2. フィクスチャ仕様（将来作る場合の入力）

すべて独自生成。商用ROM/BIOS・抜粋を含めない。`tools/make_cd_image.py` の方式（CUE/BIN, MODE1/2352,
`INDEX 01 00:00:00`）を再利用する。

1. **正常ディスク**: 先頭のデータセクターに独自の小さなHuC6280ペイロードを置く。
   - ペイロードは `disc-manifest.json` に SHA-256 を持つ。
   - 終端マーカー: ペイロードが到達時に固定のワークRAM番地へ固定バイト列（例: 16バイトの識別子 + 到達カウンタ）を書き、
     無限ループする。マーカーは**ゲストが実行された**ことの印であり、BIOS経由であることの印ではない。
     BIOS経由かは §3 の境界観測で別に判定する。
   - ブート契約が UNKNOWN の間は、ロード先・開始番地・ヘッダ形式を本書で決めない。
2. **負例ディスク**（それぞれ別ディスク）:
   - 不正セクター: ペイロードのセクターを別内容に差し替える（SHA不一致）。
   - 欠落セクター: ペイロードの後半セクターを含まない短いディスク。
   - 破損ペイロード: ヘッダは正しく本文の1バイトを反転。
   - 媒体なし: ディスクを挿入しない実行。ただし Geargrafx の no-media 実行は既存台帳で実行不能（`cd-read-contract.md` T7）。
     このケースは BLOCKED とし、成功扱いにも失敗の確認にも使わない。
3. 各ディスクの識別情報（BIN/CUEのSHA-256、ペイロードSHA-256）を証拠に記録する。

## 3. 検査仕様（境界ごとの証拠）

実コアで、BIOSをリセットから走らせ、次の境界を**別々に**観測する。観測手段は Geargrafx の公開メモリ/バス読み取り
（`tests/integration/` の既存方式）に限る。

| 境界 | 観測するもの | 判定の独立性 |
| --- | --- | --- |
| B1 リセット→BIOS起動 | リセットベクタ後の実行PC、BIOS領域内での実行 | 実コアのPC/トレース |
| B2 CD初期化 | CDコントローラレジスタへのアクセス列（`$1800` 系） | バストレース |
| B3 セクター読込 | SCSI READ(6) のCDBのLBAと件数。ディスクのどのセクターか | コアのSCSI層 |
| B4 RAM転送 | ゲストRAM上のペイロードが manifest の SHA-256 と一致 | 独立生成した参照 |
| B5 制御移譲 | ペイロード先頭へのPC到達と、終端マーカーの書込み | 実コアのPC + RAM |

- B1〜B5 のうち1つでも観測できなければ、その境界は NOT RUN。以降の境界を成功と推測しない。
- B5 だけでは不十分。B1〜B3 がBIOS側の実行である証拠（PCがBIOS領域内）と組合せて初めて「BIOS経由」を主張できる。
- 負例は、正常ディスクで B1〜B5 が揃った後にのみ意味を持つ。負例では B5 のマーカーが**書かれないこと**と、
  BIOSが偽成功を返さないこと（成功パスへ進まない）を検査する。サービスの失敗コードは ABI が UNKNOWN のため
  期待値を決めない。
