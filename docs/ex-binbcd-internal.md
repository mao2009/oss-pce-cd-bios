# EX_BINBCD 内部ルーチン（本プロジェクト独自仕様）

Issue #70。`src/ex_binbcd.s` の `ex_binbcd_packed` は本プロジェクトが独自に定めた契約で動く HuC6280 ルーチンである。**System Card の slot `$3C` / 候補 `$E0B4` の ABI ではない**。純正 EX_BINBCD の契約は未確認（Spec=HYPOTHESIS）のままで、本ルーチンの検証結果はその根拠にならない。ROM ジャンプテーブルには接続していない。

## 契約（独自）

| 項目 | 内容 |
|---|---|
| 入力 | A = 符号なし 2 進数。有効範囲は 0..99 |
| 出力（範囲内） | A = **packed BCD** 1 バイト（bit7-4 = 十の位、bit3-0 = 一の位）。C=0 |
| 範囲外（A = 100..255） | A は入力のまま、C=1。範囲外をエラーとして返すだけで、桁あふれ値は作らない |
| 保存 | X, Y を保存。D は立てない（D=1 のまま呼ばれた場合は対象外） |
| 未規定 | 戻り時の N/Z/V |
| 副作用 | RAM/IO アクセスなし。スタック使用 3 バイト（JSR 2 + PHX 1） |

unpacked BCD（1 桁 1 バイト。例: 10 → `01 00`）は提供しない。packed の 10 は 1 バイト `$10` である。

## 検証

- ホストテスト（`make test` の対象）: `tests/host/test_ex_binbcd.py`。確認するのは次の 3 点だけで、**アセンブルしたルーチンは実行しない**。
  - Python モデル `tools/ex_binbcd.py` の `binbcd_packed` が 0, 9, 10, 99, 100, 255 で期待値を返すこと、0..99 全値の桁妥当性、packed（10 → 1 バイト `$10`）と unpacked（`01 00`）の区別、バイト範囲外入力の拒否。
  - プローブ ROM のバイト固定: `CMP #100`（`C9 64`）、`ADC #$10`（`69 10`）、リセットベクタ。ルーチンのアセンブルが通り、これらのバイトが期待位置にあることだけを見る。
- 既知の限界: ループ論理を変えても `ADC #$10` と `CMP #100` のバイトが変わらなければ `make test` は通る。これを検出できるのは下記の実コア照合のみ。
- 振る舞いの検証（実コア、opt-in）: `tests/integration/geargrafx_ex_binbcd.py`（Linux、環境変数 `TOOLS_DIR` が必須）。`make test` には含まれない。共有ターゲット `routine-real-core`（PR #331）が実行する。#331 は本 PR の**後**にマージする。HuCARD プローブ `tests/fixtures/ex_binbcd_probe.s` が 0..255 全入力で A/P/X を RAM に記録し、ホストモデルと照合する。`ADC #$10` を `ADC #$20` に変えた変異 ROM が不一致になることも確認する。Geargrafx の結果は実機の挙動を証明しない。**本 PR 自体は実コア PASS を主張しない**（実コア結果は #331 側で実行・記録する）。
- 履歴の注記: 本ブランチの commit `03c8485` はホストテストファイルを空にした壊れた中間 commit で、`5b0ed2c` が復元する。73f8fe2 との正味差分はテスト 2 行のみ。履歴は書き換えない。

## 監査（Issue #70, wk/01-ex-binbcd）

ルーチン本体は変更していない。以下は独自契約に対する監査結果である。

### 振る舞い

- 0..99: 全 100 値で packed BCD を返す。実コア照合（0..255 全入力）で PASS。
- 100..255: A は入力のまま、C=1。実コア照合で PASS。
- X: 入口値 `$A5` が全入力で保存される（プローブが記録し照合）。Y はループ添字として使われ、ループ継続で保存が間接的に確かめられる。
- スタック: 3 バイト（JSR 2 + PHX 1）。範囲外経路は PHX を実行しないため釣り合う。プローブが 256 回正常に戻ることで釣り合いを間接確認する。SP を直接比較する検査は持たない。
- フラグ: C のみ規定。プローブは P の C と D を照合する。N/Z/V は未規定で照合しない。I/T は変更しない。
- D: D=0 前提。D=1 で呼ぶと `ADC`/`SBC` が 10 進補正され結果は保証されない。本ルーチンは `CLD` を実行しない（呼び出し側の責任とし、独自契約の「対象外」に既に記載）。

### 残課題（既知の限界）

- 実コア照合は Geargrafx 上の結果であり、実機の挙動を証明しない。
- `CMP #100` や `ADC #$10` を変えても、ホストの静的バイト検査だけでは通る。振る舞いの検出は実コア照合が担う。

### 参照 ABI の契約項目（spec/api_contracts.json slot 60, $E0B4）

以下はすべて UNKNOWN で、出典はない。本ルーチンの検証はいずれも参照 ABI の証拠にならない。

- 入力レジスタ（arguments）、戻り値（returns）、破壊レジスタ（clobbered）、保存レジスタ（preserved）
- スタック使用量（stack）、MPR 設定（mpr）、使用 RAM（ram）、戻りフラグ（flags）
- IRQ 状態（irq）、エラー表現（errors）、同期（synchronization）
- エントリの存在: `huc:include/hucc/pcengine.inc` の `$E0B4` は名前からの仮説（HYPOTHESIS）。`hugo:bios.c` は選択子定義であり実行エントリの証拠ではない。

これらが確定するまで、純正 `$3C` への配線・DEV_CALLABLE 化・DEV ROM ジャンプテーブルへの登録は行わない。
