# #473 呼出し側スタック契約の合成実験

## 位置づけ

- オーナー判断（#473 の Phase B）: API を JSR する時点で、呼出し側が有効な RAM スタックを保証する。
- 本書は、その契約の前提を合成 ROM と無改造の Geargrafx コア（b49ae82）で観測した結果である。本番の安全ゲートではない。#459 / #367 のゲートは解除しない。
- 対象の ROM はテスト専用の 8 KiB HuCARD（`tests/fixtures/caller_stack_contract.s`）。参照 BIOS 由来の内容は含まない。
- 実行: `tests/integration/geargrafx_caller_stack_contract.py`（Linux、TOOLS_DIR 指定）。コアやツールが無い場合は FAIL（終了コード 1）で、スキップしない。

## 方法

- ca65 / ld65 で 3 種類のビルドを作る（`CASE_RAM`、`CASE_IO`、`CASE_IRQ`）。
- 探針 `tests/integration/geargrafx_caller_stack_probe.cpp` は無改造コアを使う。
  - 1 命令ずつ `HuC6280::RunInstruction` で進める。TII は 1 バイトずつ進む（`huc6280_opcodes_inline.h` の TII 状態 2）。
  - ラベル到達時の A/X/Y/P/S/MPR、WRAM の変化（WRW）、VDC の AR/SR/R0〜R31 の変化（VDW）を記録する。
- 制限: VDC の読出しと I/O の読出しは観測していない。VDC 書込みの宛先（下表の「推定」）は、コアの I/O デコードからの推定である。観測したのは VDC 状態の差分だけ。

## 結果 1: 契約を満たす場合（MPR1 = RAM $F8）

| 項目 | JSR 直前 | RTS 後（post_return） | 判定 |
|---|---|---|---|
| A | $11 | $11 | 一致 |
| X | $22 | $22 | 一致 |
| Y | $33 | $33 | 一致 |
| P（B を除く） | $0D（別実行で $4D。I/D/C は呼出し側で設定） | 同じ | 一致 |
| S | $FF | $FF | 一致 |
| MPR0〜7 | 同じ | 同じ | 一致（MPR2〜7 の初期値は実行ごとに変わる） |
| ガードが読んだ MPR1 | $F8 | - | RAM として許可 |
| ガードのフラグ（WRAM $0210） | - | 1 | 許可を検出 |
| RTS の戻り先 | - | 呼出し直後の命令へ 1 ステップで戻る | 一致 |
| VDC 書込み | - | 0 件 | 一致 |
| スタック書込み（WRAM） | - | $01FC〜$01FF と $0210 のみ | 一致 |

JSR が積んだ戻りアドレスは WRAM $01FF = $E0、$01FE = $15 として観測された（ステップ 12）。

## 結果 2: 契約を破る場合（JSR 前に MPR1 = $FF）

| 観測 | 内容 | 根拠 |
|---|---|---|
| ガードが読んだ MPR1 | $FF（判定: 違反を検出） | TMA #$02 の直後の A |
| フラグ $0210 | 0 | ガードの RTS 到達を HITS で確認 |
| JSR（ステップ 14） | VDC R0（MAWR）が $0000 → $E019 | 戻りアドレス $E019 の 2 バイトがデータポートへ書かれた（推定: $21FF が MSB、$21FE が LSB の書込み） |
| PHP（ステップ 15） | VDC 状態の変化なし | 推定: $21FD（下位 2 bit = 01）の書込みは VDC 状態に現れない |
| PHA（ステップ 16） | VDC AR が $0000 → $0011 | A = $11 の push が $21FC（下位 2 bit = 00）への書込みで AR を変えた（推定） |
| WRAM への書込み | スタック（$01FC〜$01FF）には無し | スタックは I/O に当たった |
| RTS の戻り先 | post_return へ戻らない（情報のみ、合否には使わない） | 戻りアドレスは I/O 読出しの値になる（読出しは未観測） |

ガードの検出（違反の判定）は働いた。ただし、JSR の push・ガード自身の push は既に I/O に書き込んでいた。検出は副作用を防がない。

## 結果 3: IRQ1 と TII（8 バイト、ROM → WRAM $0220）

| ステップ | 内容 |
|---|---|
| 9 | TII の開始（PC は TII のまま） |
| 10〜17 | 1 ステップに 1 バイトずつ転送（WRAM $0220〜$0227 の書込み）。PC は TII のまま。IRQ は受理されない |
| 11 | 転送の途中（2 バイト目の後）で IRQ1 の線を assert |
| 18 | 最後のバイトで転送が完了。同じ呼出しの中で IRQ1 ベクタへ分岐（PC は `irq1_entry`） |
| 19 | IRQ1 の入口を実行 |

- 転送後の $0220〜$0227 は A1〜A8 で、期待値と一致した。
- 根拠のソース: `huc6280_inline.h:90` の `if((m_irq_pending || ...) && (m_transfer_state == 0)) HandleIRQ();`。実観測は、転送の途中では受理されず、転送完了の直後に受理された、というこの行の予測と一致した。
- 注意: 転送完了の直後に受理されるのは、この合成コアの動作である。実機のタイミングは未確認。

## 未検証・限界

- 実機の TMA・IRQ・NMI の挙動は未確認。pinned コアには NMI の受理経路が無いため、NMI は本実験の対象外（#473 の受入 7 のまま、オーナー確認が必要）。
- VDC の読出し、I/O 読出しの副作用（SR のクリアや読出しバッファ）は観測していない。
- JSR 直前の P と MPR2〜7 の初期値は、コアの乱数初期化で実行ごとに変わる。判定は差分（前後の一致）で行った。
- 契約違反は MPR1 = $FF の 1 例だけを試した。S 不足、T=1 などの他の違反は未実験。
- RAM とみなすのは WRAM バンク $F8 のみ。
- 1 回目のステップだけ `RunToVBlank` を使い、以後は `RunInstruction` を使う（コアのハードウェアクロック設定のため）。VDC のタイミングは CPU 状態の観測に影響しない想定だが、本実験では検証していない。

## 再現

```
TOOLS_DIR=<tools> python3 tests/integration/geargrafx_caller_stack_contract.py --out <dir>
```

`<dir>/caller-stack-evidence.json` に各ケースの記録（ステップごとの TRACE、WRW、VDW、XFER、IRQ）を出力する。
