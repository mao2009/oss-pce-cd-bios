# Issue #217: 純正 CD_SEEK ($04 / $E00C) JSR の安全可否裁定

## 結論
**BLOCKED。** 純正 callee の JSR は実行しない（JSR 回数 0）。次段階 #218 の判定も **BLOCKED**。

理由は次の 2 点に集約される。
1. callee のバイト列・ABI（戻り値、フラグ、エラー、完了条件）が未確認（#13 で UNKNOWN）であり、副作用集合を有限に列挙できない。
2. pinned Geargrafx `b49ae82a` 実コアには、列挙できた副作用（VDC/ST 迂回、CD デバイス書込み、IRQ、MPR 動的変更）のいずれにも、副作用発生前に一般的に遮断する手段がない（#173 / #194 / #200 / #202 / #203 の実測）。

これは「安全が確認できない」ことの裁定であり、「callee が危険である」ことの証明ではない。純正 BIOS は読み込まず、そのバイトも実行していない。

## 対象と範囲
- 対象: slot `$04` / 候補 `$E00C` `CD_SEEK`（親 #13、関連 #3 / #5 / #6 / #8 / #12 / #173）。
- 本 Issue は監査と安全な負例検証まで。純正 BIOS の JSR 実行、`./rom/syscard3.pce` の読込、バイトの抽出はいずれも行っていない。
- 既存の契約判定コード（`tools/cdreset_safety_preflight.py` など、#211〜#213 が変更中のもの）は変更していない。

## 副作用の監視範囲（fail-closed）
`tools/cdseek_safety_gate.py` の `HAZARDS` と一致する。

| ID | 副作用 | 監視・遮断の状況 | 事前遮断 |
|----|-------|-----------------|---------|
| H1 | ST0/ST1/ST2 による VDC 書込み（`WriteFromCPU` 迂回） | 検出サイトなし (#202) | 不可（NONE） |
| H2 | `$1802`/`$1402`/`$1403`/`$1804` の MMIO 書込み | 検出のみ、`$1804` は既知 PC の実行ブレークのみ (#173/#194/#200) | 既知 PC のみ |
| H3 | CD デバイス副作用（シーク命令、SCSI/CD レジスタ書込み）。ディスク・バスの不可逆変化 | ホストからのロールバック手段なし | 不可（NONE） |
| H4 | IRQ マスク/ACK 書込み、IRQ2 到達の保証なし (#201) | 書込み完遂後の検出のみ | 不可（DETECT_ONLY） |
| H5 | TAM/TMA による MPR 動的変更 | 実行後の MPR スナップショットでのみ検出 (#170) | 不可（POST_HOC） |
| H6 | 許可域外の RAM 書込み | CPU 経路は `map_write`/ブレークで検出、ST 経路は未監視 | 不可（DETECT_ONLY） |
| H7 | callee のバイト列・ABI（戻り値、フラグ、完了条件）が未確認 | 監視対象を列挙できない | 不可（NONE） |
| H8 | 命令予算超過・タイムアウト | 実行の上限のみ。副作用は防がない | 不可（POST_HOC） |

未監視経路の要点: ST0/1/2 の VDC 書込みと CD デバイス副作用は、pinned コアのいかなるフックでも捕捉できない。`$04` は CD デバイスへのシーク命令そのものが目的であるため、H3 は「副作用が起きないこと」を前提にできない。

- `$01` / `$E003` の BLOCKED 状態は変更しない。`MODEL_ELIGIBLE` 相当の表示も作らない。
