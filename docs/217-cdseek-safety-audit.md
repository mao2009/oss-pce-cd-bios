# Issue #217: 純正 CD_SEEK ($04 / $E00C) JSR の安全可否裁定

## 結論
**BLOCKED。** 純正 callee の JSR は実行しない（JSR 回数 0）。次段階 #218 の判定も **BLOCKED**。

理由は次の 2 点に集約される。
1. callee のバイト列・ABI（戻り値、フラグ、エラー、完了条件）が未確認（#13 で UNKNOWN）であり、副作用集合を有限に確定できない。
2. pinned Geargrafx `b49ae82a` 実コアには、列挙できた副作用（VDC/ST 迂回、CD デバイス書込み、IRQ、MPR 動的変更）に対して、副作用発生前に一般的に遮断する手段がない。`$1804` の既知 PC 限定の事前遮断のみ存在する（#194 / #200 の記録）。

これは「安全が確認できない」ことの裁定であり、「callee が危険である」ことの証明ではない。純正 BIOS は読み込まず、そのバイトも実行していない。

## 対象と範囲
- 対象: slot `$04` / 候補 `$E00C` `CD_SEEK`（親 #13、関連 #3 / #5 / #6 / #8 / #12 / #173）。
- 本 Issue は監査と安全な負例検証まで。純正 BIOS の JSR 実行、`./rom/syscard3.pce` の読込、バイトの抽出はいずれも行っていない。
- 既存の契約判定コード（`tools/cdreset_safety_preflight.py` など、#211〜#213 が変更中のもの）は変更していない。

### 源泉間の不整合（開示）
- `docs/cd-reset-contract.md` は #194 について「`$1804` の副作用前トラップは BLOCKED」と記す一方、`geargrafx_mmio1804_preblock.py` は既知 PC の実行ブレークによる事前遮断を GREEN と記録している。両者は「一般的な `$1804` 事前遮断」と「既知 PC の事前遮断」を区別して読む必要がある。本記録は後者のみを認める。
- `docs/173-safety-monitor-limits.md` は MPR 変更について「実行前の静的バンクページ整合チェックと実行後の動的 MPR 比較で事前阻止可能」と記す。静的チェックは既知コードに対してのみ有効であり、callee のバイト列が未確認の本件には適用できない。このため H5 は POST_HOC とした。

### 再測定の判断
上記の副作用経路は `$04` 専用の callee に依存せず、既存の合成ゲスト（ST、`$1804`、`$1802`/`$1402`/`$1403`）で既に「事前遮断不能」または「既知 PC のみ」と記録されている。`$04` callee の内容が未知である以上、追加の合成測定を重ねても callee の安全性は確定しないため、**本 Issue では新たな実コア測定を行わない**。既存の統合テストは `make integration` で再実行可能。

## 副作用の監視範囲（fail-closed）
`tools/cdseek_safety_gate.py` の `HAZARDS` と一致する。

| H3 | CD デバイス副作用（シーク命令、SCSI/CD レジスタ書込み） | 監視手段なし。ホスト側からの巻戻し手段も確認していない（推論） | 不可（NONE） |
