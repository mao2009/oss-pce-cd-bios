# RNG draw count before the observed reset state: 521 (seed A) and 520 (seed B) (C-R1, review item M-3)

Scope: synthetic BIOS and synthetic CUE, default configuration (InitRam, InitCardRam, InitArcadeCard, InitColorTable, InitRegisters, InitMPR as in `config_definitions.inc.h:202-207`). Pinned source `<EVIDENCE_ROOT>/env-geargrafx/src` (HEAD b49ae82a), read-only. No emulator launch was made for this document; the check uses the recorded synthetic states only.

## 1. Answer

The observed MPR block (stream index 521 for seed A, 520 for seed B) is the first draw of the final reset (the reset run by `load_media`). The stream index of that first draw is:

  index = 1 (SCSI init draw) + (7 + r_init) (init-time MPR loop, with r_init zero-byte rejections) + 512 (init-time HuC6260 colour table)

So seed A has r_init = 1 (index 521) and seed B has r_init = 0 (index 520). The one-draw difference between the seeds is one zero-byte rejection in the init-time MPR loop of seed A (`memory.cpp:110-114`).

**Status: ATTRIBUTED FROM SOURCE** ( the six recorded deterministic reset states are reproduced by the same draw order; the init-time draws themselves are not observed directly; see section 6).

Init (`GeargrafxCore::Init`, `geargrafx_core.cpp:100-140`):

1. `:108` Seed.
2. `:124-127` `CdRomMedia::Init`, `CdRom::Init`, `ScsiController::Init` (`:126`, R1 draw #1), `Media::Init`.
3. `:128` `Memory::Init` → `Memory::Reset` (R2 with r_init rejections, then R3-R6 fixed).
4. `:129` `HuC6260::Init` → `HuC6260::Reset` (R8, 512 draws).
5. `:133` `HuC6280::Init` (no draws).

load_bios: no draws.

load_media (`mcp_debug_adapter.cpp:1994-2015` → loader thread `emu.cpp:176-190` → `GeargrafxCore::LoadMedia` `geargrafx_core.cpp:208-215` → `Reset()` at `:213`):

6. `Reset` (`:1205-1246`): `Memory::Reset` (`:1231`, R2 with r_final rejections), `HuC6260::Reset` (`:1233`, R8), `HuC6280::Reset` (`:1236`, R9: 2 draws), `CdRom::Reset` (`:1237`, none), `ScsiController::Reset` (`:1238`, R1 draw #2).

The observed state is the state after step 6 (paused at E000 before any instruction).

## 4. The single difference between the first (Init-time) reset chain and the later (load-time) reset chain

- Init-time chain: R1 (1 draw), R2 (7 + r), R8 (512). Total 520 + r_init.
- Load-time chain: R2 (7 + r), R8 (512), **R9 (2 draws, HuC6280 registers and P)**, R1 (1 draw). Total 522 + r.

The only difference in the draw sequence is R9, the CPU A/X/Y/S/P pair. It is present only in `GeargrafxCore::Reset` (`geargrafx_core.cpp:1236`), not in the Init-time chain, because `HuC6280::Init` does not call `Reset`. The Init-time chain has no CPU reset, so the "first" reset has no CPU register draws. R1 is in both chains (in the Init chain before R2; in the load chain after R9).

## 6. What is not observed directly

- The init-time draws (R1 and R2 at init, R8 at init) are not in any record. The value r_init = 1 for seed A is derived from the stream and the source order, and it is consistent with the six final states. A direct check would need an observation at Init (for example a breakpoint in the Init path, which the MCP does not expose before `load_media`). This is noted as a limit, not a gap in the attribution.
- The colour-table values (R8) and the init-time MPR values are not compared with any record. Full initial-state equality is **not** claimed.

## 7. Startup conditions

Under the default configuration:

- BIOS load: no draws.
- Medium load (CUE, CD hardware flag, card-RAM size, SF2/arcade mapper): no draws. The CD RAM loop size depends on the medium (`memory.cpp:146`), but its draws are conditional on a random reset value, which is not the case under the default configuration (R4). The count is therefore independent of the medium.
- Init-time chain: no media is loaded yet, so its draws do not depend on the medium.

Not default (not used in C-R1): with `InitRam`, `InitCardRam` or `InitArcadeCard` set to Random, R3-R6 draw. Then the count would depend on the medium (CD hardware adds 0x10000 draws in R4) and on the card-RAM size. Any reference-BIOS A/B run must keep these options and the load order identical.
