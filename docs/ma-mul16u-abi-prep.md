# MA_MUL16U ABI 準備メモ（Issue #75、スロット `$41`）

本書は DEV 契約の準備記録であり、参照 System Card の ABI を主張しない。
参照の呼出規約（入出力レジスタ、フラグ、clobber、タイミング）はすべて **UNKNOWN** のままであり、
`spec/api_contracts.json` の該当項目、VERIFIED 状態、`release_eligible`、承認欄には一切触れない。
参照 VERIFIED は 0/81 のまま変わらない。

## 対象

| 項目 | 値 |
| --- | --- |
| 候補名 | MA_MUL16U |
| スロット | `$41`（候補エントリ `0xE0C3` は HYPOTHESIS） |
| DEV 実装 | `src/overrides/slot_41.s` |
| ホストモデル | `tools/ma_mul16u_abi_model.py`（DEV のシフト加算とは別経路の部分積和） |
| ホスト試験 | `tests/host/test_ma_mul16u_abi_prep.py` |

## DEV 契約（プロジェクト独自、参照ではない）

- 入力: 呼出側が `PHA` で被乗数 lo、被乗数 hi、乗数 lo、乗数 hi の順に 4 バイト積み `JSR` する。全 65536 x 65536 の組が有効。
- 出力: 同じ 4 バイトに 32-bit 積を上書きする。先に push したバイトから bits 0-7、8-15、16-23、24-31（リトルエンディアン）。呼出側が 4 回 `PLA` で回収する。
- 最大積: `$FFFF * $FFFF = $FFFE0001`。バイト列は `01 00 FE FF`。
- 繰り上がり（carry）: 16-bit 境界の繰り上がりは高ワード加算内で処理する。`$8000 * 2 = $00010000` が境界例。
- 保持: Y と P。P は入口で `PHP` した値を `PLP` で戻す（T は 0 で戻る前提。`slot_41.s` の注記参照）。
- 破壊（clobber）: A と X。
- メモリ: スタックページ `$2100-$21FF` のみ。ゼロページと固定 RAM は使わない。I/O なし。割り込みフラグ I は変えない。

## 検証内容

| 観点 | 手段 | 結果 |
| --- | --- | --- |
| 32-bit 形式とバイト順 | 最大積、小さい積のバイト列を固定値で照合 | RED の後 GREEN |
| 繰り上がり境界 | `$8000*2`、`$00FF*$0101`、`$0100*$0100` | RED の後 GREEN |
| 独立経路との一致 | 境界値 11 種の全組合せを `m*q` と照合 | RED の後 GREEN |
| 書き込み範囲 | `slot_41.s` の絶対書き込み先が `$2100-$21FF` 内であることを静的確認 | RED の後 GREEN |

既存の `tests/host/test_ma_mul16u_dev.py`（全 multiplier を 12 被乗数で走査）は DEV 実装の並列モデルであり、本書の検証はそれを補うもので置き換えない。

## UNKNOWN 項目（参照 ABI）

- 参照の入力レジスタ、出力レジスタ（A/X/Y の扱い）、戻り値の置き場所。
- 参照の carry、Z、N の結果フラグ。
- 参照の clobber 範囲（ゼロページ、固定 RAM の使用有無）。
- 参照のエントリ `0xE0C3` の実在。`hugo:bios.c` 側は HLE セレクタであり実行可能エントリの証拠ではない。
- タイミングとエラー時の挙動。
- 参照の 32-bit 積の格納形式（バイト順、ワード配置）。

## BLOCKED 条件

- 参照 BIOS の callee の実行、または JSR による参照呼出しは本 Issue では行わない。参照 ABI の確定にはオーナー承認と別の検証 Issue が必要。
- Geargrafx による実コア試験は本準備では実行しない（重い実行のため別途スロットロック下で扱う）。

## 結論

DEV 契約の 32-bit 形式、バイト順、繰り上がり、最大積、clobber 範囲は独立ホストモデルで固定した。
参照 ABI は UNKNOWN のままで、VERIFIED や DEV_CALLABLE の主張は行わない。マージ推奨は、ホスト試験の GREEN と独立レビューの承認が揃った時点で、ドラフトのまま判断を仰ぐ。
