# CD_PCMRD（$0E、候補エントリ $E02A）caller ABI・戻り値の出典別裁定（Issue #276）

親: #23（CD_PCMRD）。**状態: BLOCKED_ABI を維持。release_eligible=false。DEV_CALLABLE なし。**
本書は公開出典の記述を並べて裁定するものであり、System Card BIOS の実行・測定は行っていない。
したがって本書の事実は、どれも「呼出先の振る舞いが確認された」ことを意味しない。

## 1. 規則

ラベルの意味（本書内でのみ使う。BIOS 実測の OBSERVED は使わない）:

- `SOURCE_FACT`: 出典本文に明記されている内容。単一出典の場合も含む。呼出先の振る舞いとしては未検証。
- `HYPOTHESIS`: 出典から推測したが、出典本文には明記されていない。
- `UNKNOWN`: 出典が不足、または出典同士が食い違う。推測で埋めない。成功値・失敗値も定義しない。

不一致の扱い: 出典が食い違う項目は統合せず、`conflict unresolved` と明記する。どの出典も、他の出典より正しいとは扱わない。

除外する証拠:

- Hu-Go `bios.c` の処理は HLE（エミュレータ内の模擬実装）であり、BIOS の ABI の証拠ではない。内容は参照のみとし、ABI の根拠にしない。
- `include/hucc/hucc-systemcard.asm` 125 行の `$0E` は **`cd_fade` の引数**（ADPCM フェードアウト）であり、CD_PCMRD ではない。
  同じ番号でも別関数であるため、CD_PCMRD の根拠にしない。
- 本リポジトリの DEV ROM、ホスト算術、合成テストは BIOS の証拠ではない。

## 5. 未解決の矛盾（conflict unresolved）

- **C1（出力 X/Y の有無）**: S5 は X/Y を出力と記す。S7 は X/Y を変えない。S7 は HLE であり、判定に使えないため、矛盾は解決せず残す。
- **C2（エラー位置の内部矛盾）**: S5 は `A` のエラーを $1803 の先頭ビットで示すと記し、同じ節で `$00` ok / `$01` error とも記す。
  どちらが呼出先の仕様かは出典から決まらない。
- **C4（関数番号 `$0E` の出典不一致）**: S5 は CD_PCMRD の番号を `$0E` とする。ピン留めした HuC（S1/S2）には CD_PCMRD の番号・呼出しがなく、
  `hucc-systemcard.asm` 125 行の `$0E` は `cd_fade` の引数（S4）である。S7 の `$0E`（HLE）は判定に使えない。
  番号の対応は出典から確定せず、conflict unresolved として残す。
- **C3（`A` の意味）**: S5 は `A` をエラー状態とし、S7 は `A` を `$41` の値として返す。HLE であっても、出力の意味の食い違いとして残す。

いずれの矛盾も、本書では解決していない。解決したと書く箇所はない。

## 6. 結論

- CD_PCMRD の ABI（入力・出力・フラグ・副作用・タイムアウト）は **未確定（UNKNOWN）**。
- 出典が確認できたのは入口アドレス `$00:E02A` のみ（SOURCE_FACT、S1 単独）。関数番号 `$0E` は HYPOTHESIS で、出典の食い違い（C4）が残る。
- ABI の裁定に必要な呼出先の実行（実機・エミュレータ上の System Card BIOS）は、本作業では行わない。**NOT_RUN**。
- 公開 caller（HuC）に CD_PCMRD の呼出しがないため、caller 側からの ABI 根拠は得られない。
